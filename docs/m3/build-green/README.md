# BUILD-GREEN v1

`mvn -B -ntp verify` of the SwingX superset passes on JDK 17 and 21, from the root reactor through
BeanInfo, Complete (`swingx-all`) and the Demos. Before this recipe, `swingx-core` had 20 failing tests on
JDK 21 and the demos could not resolve their dependencies on any JDK from 9 up.

| File | Role |
|------|------|
| `build_green_fixes.py` | The recipe: anchored, idempotent operations R1..R8. A second run prints `ALREADY` for every operation. It reuses the `Doc`/`insert`/`replace` kernel of `../api-census/restore_lost_api.py`. |
| `RECIPE_MEMORY.tsv` | One row per correction: what triggered it, what was wrong, what the recipe does instead, and the evidence. |
| `TEST_BASELINE.tsv` | Every test that failed in any run, with its status on the superset before the recipe, on upstream master (JDK 21 and 17), the cause, the resolution and the status after. Generated by `baseline_table.py` from `runs/*.tsv`. |
| `upstream_baseline.py` | Adapts an upstream master worktree (9e33bc0) just enough to compile on JDK 17/21, so that the same tests can run there. The tested classes stay as upstream wrote them. |
| `surefire_failures.py` | Reads surefire XML reports and writes one TSV row per failing test (the `runs/` files). |

## Resolutions

- **Environment pins (R1).** The root `pom.xml` passes `${swingx.test.argLine}` to every forked test JVM:
  JDK 6 era locale data (`java.locale.providers=COMPAT,CLDR`), UTC and `en_US`, which are the defaults of
  the GitHub runner. COMPAT exists from JDK 9 to JDK 22; JDK 23+ will need these tests to set their
  calendar's week rules explicitly.
- **Fixes in main code.** `JVM` recognises JEP 223 versions (R2); `JXEditorPane` incremental search
  keeps its state on JDK 9+ (R3); the demos look the Java Web Start services up reflectively (R7).
- **Fixes in tests.** `JXHeaderTest` runs its `setUp()` (R4); `JXTreeTableUnitTest` expands a fixed model
  instead of the first entry of the drive root (R5).
- **Exclusion with evidence.** `BuddyLayoutAndBorderTest.testPreferredWidth` is skipped on JDK 9+ only
  (R6); upstream master fails it identically on JDK 17 and 21 (`TEST_BASELINE.tsv`).
- **Exclusion where the premise cannot hold (R8).** `LookAndFeelAddonsSandboxTest.testSystemAddon` assumes
  that the system look and feel is not the cross-platform one. On Linux without a GNOME desktop
  (`XDG_CURRENT_DESKTOP`) or GTK, `UIManager.getSystemLookAndFeelClassName()` is Metal, the cross-platform
  LAF, and `getBestMatchAddonClassName()` checks the cross-platform name first, so the Metal addon is the
  correct answer. The test is skipped only where the two class names are equal; upstream master fails it
  identically on such a Linux, on Temurin 21 and 17 (`runs/linux-*.tsv`, `TEST_BASELINE.tsv`). CI
  (`.github/workflows/maven.yml`) installs GTK 3 and sets `XDG_CURRENT_DESKTOP=GNOME`: `UNIXToolkit.getDesktop()`
  then reports GNOME on Temurin 11, 17 and 21, the system LAF is `GTKLookAndFeel` (the probe step prints it)
  and the test runs on Linux too (`runs/linux-*-gnome.tsv`: no failures). A headless JDK (no `libawt_xawt`,
  for example Ubuntu's `openjdk-21-jdk-headless`) always answers Metal, so the test is skipped there.

## Re-running

```bash
python docs/m3/build-green/build_green_fixes.py .          # recipe; must print ALREADY on a green tree
mvn -B -ntp verify                                         # JDK 17 or 21

# upstream evidence, in a scratch worktree of origin/master
git worktree add --detach ../swingx-master origin/master
python docs/m3/build-green/upstream_baseline.py ../swingx-master origin/m3/github-donors-superset-20261031
(cd ../swingx-master && mvn -B -ntp -pl swingx-core -am -DfailIfNoTests=false \
   -Dmaven.test.failure.ignore=true -Dtest=CalendarUtilsTest,JXHeaderTest,JXMonthViewTest,JXTreeTableUnitTest,BasicMonthViewUITest,BuddyLayoutAndBorderTest,PromptTextAreaUITest,PromptTextFieldUITest,FindTest test)
python docs/m3/build-green/surefire_failures.py ../swingx-master upstream-jdk21 > docs/m3/build-green/runs/upstream-jdk21.tsv
python docs/m3/build-green/baseline_table.py docs/m3/build-green

# R8 on Linux (Ubuntu 24.04, Temurin 21 or 17 with libawt_xawt, xvfb): without a GNOME desktop the system LAF
# is Metal and the test fails on upstream master; with XDG_CURRENT_DESKTOP=GNOME and GTK 3 it is GTK and passes
(cd ../swingx-master && env -u XDG_CURRENT_DESKTOP xvfb-run -a mvn -B -ntp -pl swingx-plaf -am \
   -DfailIfNoTests=false -Dmaven.test.failure.ignore=true -Dtest=LookAndFeelAddonsSandboxTest test)
python docs/m3/build-green/surefire_failures.py ../swingx-master linux-upstream-jdk21 > docs/m3/build-green/runs/linux-upstream-jdk21.tsv
(cd ../swingx-master && env XDG_CURRENT_DESKTOP=GNOME xvfb-run -a mvn -B -ntp -pl swingx-plaf -am \
   -DfailIfNoTests=false -Dmaven.test.failure.ignore=true -Dtest=LookAndFeelAddonsSandboxTest test)
python docs/m3/build-green/surefire_failures.py ../swingx-master linux-upstream-jdk21-gnome > docs/m3/build-green/runs/linux-upstream-jdk21-gnome.tsv
python docs/m3/build-green/baseline_table.py docs/m3/build-green
```
